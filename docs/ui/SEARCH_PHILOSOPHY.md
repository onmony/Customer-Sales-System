# Search Philosophy

Search is not just a feature; it is a primary mode of interaction and navigation for professional users handling large volumes of data. It must be fast, intelligent, and deeply integrated into workflows.

## Core Principles

### Search is a Primary Interaction
Users should be able to rely on search as their fastest route to data, bypassing hierarchical navigation for specific lookups.

### Global Search
A ubiquitous search bar must be accessible from anywhere in the application, allowing users to find any entity (customer, order, invoice, product) across the entire system.

### Workspace Search
Within specific workspaces (e.g., a customer list or an order queue), provide targeted, contextual search that quickly filters the relevant data set.

### Smart Suggestions
Search should provide immediate, intelligent suggestions as the user types, anticipating their needs based on recent activity, frequently accessed records, and context.

### Multi-Faceted Entities
Search must effortlessly handle lookups by:
*   **Customer** (Name, ID, Phone, Email)
*   **Order** (Order Number, Customer Reference)
*   **Invoice** (Invoice Number, Status)
*   **Payment** (Reference, Amount)

### Search Should Reduce Navigation
A successful search should take the user directly to the desired record or workspace, effectively bypassing multi-step navigation paths.

### Actionable Search Results
Search results should not just be links. They must provide enough immediate context (e.g., status, key dates, amounts) to allow the user to make a decision or take an action directly from the results list, if applicable.
